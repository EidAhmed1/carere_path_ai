# مسارات الذكاء الاصطناعي

موقع Next.js فيه صفحتين:
- **الصفحة الرئيسية `/`** — الموقع العام يلي بيشوفه الزوار (المسارات، تفاصيلها، خط سير التعلّم والمصادر).
- **`/admin`** — لوحة إدارة محمية بكلمة مرور لإضافة/تعديل/حذف المسارات والمواضيع ومصادرها.

البيانات محفوظة بقاعدة بيانات Postgres حقيقية (مش تخزين مؤقت بالمتصفح)، فأي تعديل من `/admin` بينعكس فورًا على كل الزوار.

---

## 1. التشغيل محليًا

```bash
npm install
cp .env.example .env.local
```

افتح `.env.local` وعبّي:
- `DATABASE_URL` — رابط قاعدة بيانات Postgres (تقدر تسوي وحدة مجانية على [neon.tech](https://neon.tech) خلال دقيقتين).
- `ADMIN_PASSWORD` — كلمة المرور يلي رح تستخدمها لتسجيل الدخول على `/admin`.
- `ADMIN_SESSION_SECRET` — أي نص عشوائي طويل (مثال: شغّل `openssl rand -hex 32` بالتيرمنال وانسخ الناتج).

```bash
npm run dev
```

افتح `http://localhost:3000`. أول ما تفتح الصفحة، الكود بيتأكد إن جدول `career_paths` موجود بقاعدة البيانات، ولو كان فاضي بيعبّيه تلقائيًا بالمسارات السبعة الأساسية.

---

## 2. الرفع على Vercel

1. ارفع هذا المجلد على مستودع GitHub جديد.
2. ادخل [vercel.com](https://vercel.com) → New Project → اختر المستودع.
3. قبل الـ Deploy، روح على تبويب **Storage** بمشروع Vercel → **Connect Database** → اختر **Neon** (أو Supabase / أي Postgres من الـ Marketplace) → أنشئ قاعدة بيانات جديدة.
   - هاد بيضيف متغير `DATABASE_URL` تلقائيًا لمشروعك، ما بتحتاج تكتبه يدويًا.
4. روح على **Settings → Environment Variables** وضيف:
   - `ADMIN_PASSWORD` = كلمة المرور يلي بدك تستخدمها
   - `ADMIN_SESSION_SECRET` = نص عشوائي طويل
5. اضغط **Deploy**.
6. أول زيارة للموقع بعد النشر بتعبّي قاعدة البيانات تلقائيًا بالمسارات الأساسية — ما في خطوة يدوية إضافية.

بعد هيك، ادخل `your-domain.vercel.app/admin`، سجّل دخول بكلمة المرور، وابدأ تضيف/تعدّل/تحذف المسارات والمواضيع وروابط المصادر.

---

## 3. ملاحظة عن الحماية

حماية `/admin` هون بسيطة ومناسبة لمشروع طلابي/مجتمعي: كلمة مرور واحدة مشتركة، مش نظام حسابات متعدد بصلاحيات. كافية لمنع أي زائر عادي من التعديل بالغلط، بس مش بديل عن نظام مصادقة حقيقي لو صار عندك أكثر من شخص بيدير المحتوى أو بيانات حساسة.

---

## 4. بنية المشروع

```
app/
  page.js              → الصفحة الرئيسية (Server Component يجيب البيانات من قاعدة البيانات)
  admin/page.js         → لوحة الإدارة (محمية بـ middleware.js)
  admin/login/page.js   → صفحة تسجيل الدخول
  api/paths/route.js    → GET (عام) و POST (محمي) لكل المسارات
  api/paths/[id]/route.js → PUT و DELETE (محمية) لمسار واحد
  api/admin/login|logout/route.js → تسجيل الدخول والخروج
  globals.css            → كل التصميم (Dark/Light theme, الأنيميشن, إلخ)
components/
  PublicSite.js          → واجهة الموقع العام كاملة
  AdminApp.js             → واجهة لوحة الإدارة كاملة
  NeuralCanvas.js / HeroIllustration.js / Icons.js
lib/
  db.js                   → الاتصال بقاعدة البيانات + إنشاء الجدول تلقائيًا + كل عمليات CRUD
  defaultPaths.js         → بيانات البذرة (المسارات السبعة الأساسية)
  hooks.js                → hooks مشتركة (الثيم، الحركة عند السكرول، إلخ)
middleware.js             → يحمي /admin وطلبات التعديل على /api/paths
```
